Matching audiobook narration to text

The problem

Given a passage in an ebook, where does it begin and end in the audiobook? The book gives us the words, and the recording gives us a timeline. Connecting the two gets tricky when the narrator repeats a line or reads a heading differently from the printed version.

What I built

I built the Python alignment pipeline and deployed a dedicated GPU inference service to production. The pipeline runs under Apache Airflow. It prepares the book text and uses FFmpeg to split the narration into short, overlapping audio windows.

The GPU service has a narrow contract. It receives one audio window, runs Wav2Vec2, and returns a score for each possible speech token at each time step. The processor uses those scores to align the book text with the recording and place each match on the original audiobook timeline.

An engineering detail

A passage can span two audio windows. Simply joining their results would count part of the recording twice. The processor uses the model’s frame timing to trim the overlap and map the remaining frames back to their positions in the source audio. That gives both windows a common clock.

Result

The GPU service runs in production. The pipeline assembles the chapter timings into a SMIL synchronization map that links ebook passages to audio intervals. It validates the map before reporting the outcome to the calling system.
